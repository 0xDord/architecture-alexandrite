# architecture-alexandrite

Трейсингом следует покрыть все вызовы API: Shop API, CRM API, MES API
А также запросы к S3, так как в случае недоступности хранилища и отсутсвия ретраев заказ может потеряться.
Отправка событий в RabbitMQ тоже должна сопровождаться трейсингом, чтобы отслеживать полный путь заказа: MES -> Queue -> CRM

Список данных, которые должны попадать в трейсинг:
1) Уникальный идентификатор всей цепочки запросов - trace_id 
2) Уникальный идентификатор конкретного спана внутри трейса - span_id
3) Идентификатор заказа - order_id
4) Название сервиса, в котором совершается операция - service_name
5) Название операции - operation_name

### Мотивация
Трейсинг нужен, чтобы определить на каком этапе межсервисного взаимодействия возникла проблема и своевременно её устранить.
Такая проблема может быть не массовой и без трейсинга её будет очень сложно отловить, потратить много времени разработчиков для выяснения причины только по логам,
а ущерб от этой проблемы весьма существенный для бизнеса, как в случае с потерей заказов. Сейчас надо определить на каком взаимодейсвии они теряются.
Внедрив трейсинг запросов, у разработчика перед газалми будет вся картина пути запроса, что ускорит фиксы.

Технические матрики:
Измерение задержки ответов между сервисами
Определение сервиса на пути запроса, который отвечает ошибкой 
Определение процента ошибок от сервисов

Бизнесовые метрики: 
Время выполнения операции создания заказа через Shop API
Время открытия первой страницы через MES API оператором 
Время на прохождение заказа по различным статусам в системе
Процент успешно/неуспешно завершенных бизнес событий

### Предлагаемое решение
Трейсинг будет реализован с помощью Jaeger — один из популярных инструментов трейсинга.
Сначала нужно на хосте развернуть Jaeger из docker-compose.
Потом доработать бэкенд сервисы Shop API, CRM API, MES API. Подключить OpenTelemetry SdK, прописать в конфигурации роуты до Jaeger и добавить на эндпоинты trace-id, span-id.
Для того чтобы создавались спаны при вызове s3, используем opentelemetry-instrumentation-aws-sdk, а для создания спанов при вызове rabbitMq используем opentelemetry-instrumentation-spring-amqp.
Для вызовов базы данных используем opentelemetry-instrumentation-jdbc.

### Компромиссы
Трейсинг не принесет особо пользы в монолитной системе, где нет вызовов распределенных сервисов и внешних систем. 

### Безопасность
Меры для предотвращения несанкционированного доступа для системы трейсинга:
1) Не передавать в трейсы конфиденциальную информацию, либо маскировать её
2) Доступ к Jaeger UI должен быть только у DevOps, SRE и сотрудников сопровождения, согласно принципу наименьших привелегий
