# architecture-alexandrite

### Мотивация 
Сейчас в моменте сложно судить о состоянии системы, оперативно определять где и когда происходят сбои, а также своевременно реагировать на нештатное поведение системы. 
Клиенты долго ждут выполнение заказа при этом производственны мощности готовы к обработке этих заказов, получается что мощности простаивают из-за неоптимального взаимодействия между компонентами системы.
Для выявления узких мест и корневых причин в неоптимальной работе системы нужно собрать больше информации, как о бизнесовых метриках и сбоях в событийной модели, так и о ситуации с инфраструктурой системы.
Как следствие, внедрение мониторинга позволит решить эти проблемы, ускорить рабочий процесс, увеличить быстродействие системы, получить ценные бизнес-инсайты и повысить удовлетворённость пользователей.

### Выбор подхода к мониторингу
Четыре золотых сигнала от Google - для Shop API, CRM API, MES API 
USE - мониторинг ресурсов хостов, S3
RED - Shop Db, MES Db, RabbitMq

### Метрики 
| Название метрики                                   | Обоснование                                                                                                                                                                                                     | Ярлыки (метки)                                                |
|----------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------|
| Number of dead-letter-exchange letters in RabbitMQ | Позволяет выявить проблемы у потребителей и мониторить битые данные, непрошедшие валидацию на потребителе, а также потерянные операции                                                                          | queue, reason(причина попадания, например nack/reject/maxlen) |
| Number of requests (RPS) for internet shop API     | Для оценки нагрузки(также определение пиков, DDOS) на бэкенд                                                                                                                                                    | service, endpoint, method, status_code, ip                    |
| CPU %                                              | Для оценки нагрузки на бэкенд сервисы                                                                                                                                                                           | service                                                       |
| Memory Utilisation                                 | Для оценки потребления памяти приложением, быстрого выявления memory leak                                                                                                                                       | service                                                       |
| Response time (latency)                            | Выявление сетевых проблем и сложностей с обработкой запросов на сервисах бэкенда                                                                                                                                | service, endpoint, method, status_code, ip                    |
| Bucket Size Bytes (S3 size)                        | Заранее выявить, что места в хранилище остается мало                                                                                                                                                            |                                                               |
| Database Size                                      | Заранее выявить, что память в БД заполнена до определенного лимита                                                                                                                                              | db_instance                                                   |
| Kb tranferred (received)                           | Контроль сетевой нагрузки, балансировка нагрузки, диагнозтика проблем с трафиком                                                                                                                                | service                                                       |
| Kb provided (sent)                                 | Контроль сетевой нагрузки, балансировка нагрузки, диагнозтика проблем с трафиком                                                                                                                                | service                                                       |

### План действий
1) Определить метрики для мониторинга (таблица выше)
2) Подготовить сервисы для сборка метрик, настроить эндпоинты, которые будут отдавать метрики
3) Собрать данные по метрикам, используя Prometheus: Развернуть http сервер с API, развернуть Time-Series базу данных (TSDB)
4) Развернуть Grafana для визуализации метрик
